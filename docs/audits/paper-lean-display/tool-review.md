# Independent audit of the paper–Lean audit tool

Reviewed read-only at formal-repo base `87bce83806c757ade36d455d785b506ebd03a1b2`, focusing on `tools/paper_lean_audit/{lean.mjs,build.mjs,texhtml.mjs}`, its tests, and the paired HTML/PDF in `/tmp/stafford-audit-display-final/`. No canonical files were changed. Baseline `npm test` passed 37/37 tests.

## Confirmed correctness findings

1. **Declaration excerpts omit active Lean context.** `lean.mjs:116–161` starts at the declaration, optional docstring, and attributes; it does not surface active `universe`, `variable`, `include`/`omit`, local instance, `open scoped`, or local-notation commands. This drops assumptions and sometimes the local instances needed to read the displayed declaration. It occurs in current mapped sources: `Stafford38/Weyl/OuterOreMonic.lean:31–42` supplies `k`, `[Field k]`, and three local instances before the mapped declaration at line 44; `Stafford38/Characteristic/PostScalarExtensionPoisson.lean:24–26` supplies its ambient field/algebra/index variables. The rendered `presentedOuterPolynomial` excerpt contains the declaration body but none of its preceding context. A valid scratch theorem using `variable (R : Type*) [Ring R]` likewise renders without those assumptions. Surface source-linked active context and label it as available scope, not as a claim that every displayed variable is a required hypothesis.

2. **Blank lines silently truncate definition excerpts.** In `lean.mjs:138–142`, body mode breaks on the first blank line without setting `truncated`. A Lean-compiled scratch fixture with blank-separated pattern equations rendered only `| 0 => 0`; a blank-separated `structure` rendered only its first field. Both returned `truncated: false`, so the page gives no indication that later branches/fields were dropped. Continue through blank lines until a real declaration/scope boundary or the excerpt limit; if an excerpt must stop, flag it as truncated.

3. **A tactic body on the line after `:=` is included accidentally.** The `/:=\s*by/` check in `lean.mjs:139–142` only recognizes `:= by` on one physical line. A valid scratch `def answer : Nat :=` followed by an indented `by; exact 42` is rendered with the tactic body and `truncated: false`, unlike the same definition written `:= by` on one line. Detect the first body token across whitespace/comments and apply one consistent rule. This is an overinclusive counterpart to the silent-truncation bug.

4. **Automatic named-result resolution is not Lean name resolution.** `build.mjs:295–323` indexes definitions by repository and FQN, then searches only prefixes of the theorem namespace. It ignores active section variables and `open` declarations; `definitionCatalog.set` at line 310 also silently overwrites duplicate FQNs.

   - **False expansion from variable shadowing:** a Lean-compiled scratch file defines `Foo.P : Prop := True`, then declares in a section `variable (P : Prop); theorem target (h : P) : P := h`. The actual theorem type is `{P : Prop} → P → P`. The disposable build passes `--check` but renders the unrelated `Foo.P` as the definition of the theorem’s result.
   - **False unavailable note under `open`:** a compiled fixture defines `PredicateLibrary.Holds`, opens that namespace, and states `Foo.target : Holds`. The disposable build passes `--check`, but omits the mapped definition and says `Holds` could not be resolved in the mapped files.
   - **Wrong-file selection on duplicate FQNs:** separately compiled modules can each define `Foo.P`; a target module importing the `True` definition from A compiles, while an unrelated mapped B defines the same FQN as `False`. In helper-level reproduction, indexing T, A, B in that order selects and excerpts `B.lean` (`def P : Prop := False`). The frozen map indexes 132 referenced files and contains 19 duplicate FQN entries; I found no current automatic expansion selecting a different file than its theorem’s own file, but the last-wins behavior is unsafe.

   Respect active variable/open scope where supported, and never guess among multiple source candidates. For ambiguous/unavailable cases, require an explicit file-pinned `expands` reference or report the ambiguity without attaching a possibly wrong definition.

5. **The Lean column header names the wrong repository on external-source cards.** `build.mjs:545` hard-codes `(stafford38-formal @ …)` for every card. In the generated page, `global-stafford` has that header while its actual block is `GlobalStafford · GlobalStafford/Assembly/Closure.lean:221`; the `conv:pair` card also has an AlgebraicAnalysis reference under the formal-only header. Individual blocks use the correct repo, file, and pinned link. Render the repositories actually represented in the card or remove the fixed formal pin from that header.

6. **Review hashes omit the review rubric.** `build.mjs:561–567` hashes source commits, the item, paper excerpt, Lean info, and expansions, but not `map.review_checks`. In a disposable end-to-end build, I seeded a committed review record with every check true, changed the sole criterion label from “Check statement” to “Check for counterexample and statement fidelity,” and rebuilt. The card hash was unchanged and the old record remained “signed off.” Include check IDs and labels (and any other mutable review semantics the sign-off is intended to certify) in the hash basis. The current basis also omits `map.vocab` meanings/labels; decide whether changes to those definitions should invalidate sign-offs and encode that policy explicitly.

## Checks that passed

- The resolver uses each reference’s repo key and pinned commit for `git show`, source hash, and GitHub URL. External blocks carry their correct source repo/file. The wrong repo label above is the card header, not an incorrect source excerpt.
- Supporting declarations render in a collapsed “Supporting declarations (full signatures)” block. The frozen map has 29 direct helper refs and no `steps` arrays; the test fixture exercises step declaration signatures. I found no missing helper/step signature in the generated page.
- I compared all 319 HTML `pre.lean-src` text blocks against the paired PDF text after removing repeated PDF page headers/footers. All 319 excerpts match exactly. The PDF print path opens all `<details>` before printing; no material HTML/PDF content discrepancy was found. Page breaks can split long blocks, but the text remains present.
